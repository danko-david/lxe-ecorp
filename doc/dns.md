# dns

CoreDNS at the static address `NET_DNS`. Its whole configuration is generated by the
[controller](controller.md) into `data/dns/` and reloaded by CoreDNS on change.

## Names of containers

Every running container on this docker host gets records in the zone
`ECORP_DNS_CORE_ZONE_NAME`:

- its docker DNS names: the compose service name and the container name, so `gitlab` of this
  stack is `gitlab.e-corp.intra.net` with the defaults,
- every name in its `dns_names` label (space separated).

The zone file is `data/dns/zones/dynamic/docker/<zone>` and is rewritten whenever a container
starts or stops. Other zone files placed under `data/dns/zones/` are served too.

## Delegated names

A container with the label `dns_mode=delegated` runs a DNS server of its own, typically a
project server with a network behind it. For each of its names:

- requests for `<name>.<zone>` and everything below it are forwarded to the container,
- the address of the container itself is available as `<name>.ecorp-original-ip.<zone>`.

## Everything else

Is forwarded to the resolvers of the docker host.

## Resolution path

A container asks the [dc](dc.md) (`NET_DC`), which answers for the domain and forwards the rest
here. A machine outside the stack that should resolve these names needs `NET_DC` as its DNS
server and a route to `NET_CIDR`.
